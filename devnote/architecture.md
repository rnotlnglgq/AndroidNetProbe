# 组件职责与数据契约

## 当前起点

主代码约 3000 行 Kotlin，探针已有独立文件，地址、订阅和公网结果已有专用数据结构；JVM、JNI 主机与设备测试均有基础。主要耦合集中在 ViewModel 的任务控制，以及采集、展示、导出之间的字段约定。

当前权限实验将已合并手动结果的快照保存为基线，随后用基础采集结果比较，可能把手动栏目识别为消失。第一阶段先固定这一边界，再调整组件。

## 职责与依赖

| 组件 | 职责 | 边界 |
|---|---|---|
| Activity 与 Compose | 接收生命周期、申请权限、启动文件选择器，展示栏目与操作结果 | Android 界面和资源解析留在此处 |
| ViewModel | 接收用户动作，组合 `UiState`，转发读取与导出请求 | 依赖会话、仓库和导出接口，通过 `StateFlow` 提供状态 |
| 采集会话 | 管理前台有效期、开关、采样合并、手动任务和取消 | 调用平台探针，串行提交有效结果到仓库 |
| 快照仓库 | 保存各栏目最近结果，统一组装快照，发布状态 | 数据处理使用 Kotlin，Android 服务由探针持有 |
| 平台探针 | 读取系统 API、JNI、进程和网络，释放各自资源 | 返回字段、状态、来源、采集时间及诊断代码 |
| 字段定义与规则 | 定义稳定键、权限条件、敏感等级、栏目归属及对照规则 | 以纯数据供采集、投影和导出使用 |
| 展示投影 | 将领域结果映射为摘要、资源键和格式化参数 | 使用界面语言，保留原始值供复制 |
| 导出适配器 | 将快照映射到版本化 JSON，执行遮挡并写入用户选定位置 | Android 文件写入与纯 JSON 转换分别实现 |

在应用入口以构造参数集中装配依赖，ViewModel 通过 Factory 创建。只有跨组件、平台边界和测试替身需要接口。现阶段使用包组织这些职责；Gradle 模块拆分留给明确的独立构建或复用需求。

## 字段与权限

每个探针维护自己的字段定义：稳定键、值类型、所属栏目、来源、敏感等级和权限条件。接口、订阅等集合由定义加实例标识生成现有 JSON 路径；界面按栏目与实例分组。标题和摘要布局归展示层所有。

权限条件分别表达字段读取、前置对象获取与运行条件，支持 AllOf、AnyOf、API 范围和设备 feature。普通权限与运行时权限使用同一组权限标识，由展示投影决定授权提示。位置开关等系统条件单独表达。

例如，订阅名称的 getter 可以直接读取，但枚举订阅对象需要电话权限；服务状态需要结合前置对象和位置条件。两类信息均从同一份定义生成提示与技术详情。

字段构造时必须指定敏感等级。字段状态、诊断原因和原始值分别保存；空结果、权限拒绝、系统遮挡、用户关闭和读取失败继续沿用各自语义。异常只保存安全的类型或原因代码。

## 快照与权限对照

仓库按栏目保存最近结果，每份结果带开始时间、完成时间与会话标识。基础刷新替换本轮基础栏目；手动读取替换对应栏目。组装器从同一次仓库状态生成不可变快照，并检查重复字段路径。

UI、JSON 预览、导出和权限对照都从这个入口获取快照。手动结果保留自身时间，界面显示其最近读取时间。导出在用户发起时固定快照和事件记录，文件选择过程沿用这份内容。

权限实验保存完整的前后快照用于核查。`changedPaths` 比较字段状态与结构化值，权限说明等定义元数据保持可查询；采集时间等易变字段从差异判定中分离。当前模块成员资格保持一致，存在、缺失和状态变化分别处理。

集合字段以接口名、会话内订阅别名识别实体，再映射到路径，减少顺序变动造成的差异。对照表示两次观测的变化，权限归因由用户结合网络条件判断。

## 任务与生命周期

采集会话在前台开启，退出前台时注销回调、取消任务并使当前会话失效。每个读取任务记录会话与请求标识，提交时同时检查其有效性和对应开关。旧会话的延迟结果在提交边界丢弃。

连续基础刷新合并为最新请求；同类手动任务至多执行一个。UI 的 busy 状态来自任务状态，结果与状态通过同一提交入口更新。会话共享时钟与可注入调度器，便于确定性测试。

通用控制只负责启动、取消、状态和提交。资源释放由适配器实现：HTTPS 关闭连接，getprop 终止进程，网络观察者注销回调；JNI 调用返回前保留占用标记，防止重入。取消异常继续向上传播，字段读取和模块容错统一遵守该约定。

权限撤回或实验关闭时，仓库清除对应受限缓存并发布状态。权限实验的历史基线独立管理，保留到用户重设基线、关闭对应实验或进程结束；从系统权限设置返回后继续使用原基线。导出显式固定的内容按该次操作管理。

## 复用范围

保留并整理 `Panel`、地址摘要、复制值、权限提示、技术详情和子页签。为大型栏目使用专用展示投影，共用字段索引。页面项分别放入 LazyColumn，按稳定键保存选择状态。

JNI、getprop 和公网检测保留各自适配器及测试。新增探针遵循“字段定义、结果、适配器、投影、测试”的接入路径；共享接口只覆盖真正相同的能力。

## JSON 兼容与验证

导出 DTO 与内部运行状态分离，字段名显式固定。保持现有路径、状态枚举和 JSON 1.0 结构；内部权限表达、诊断代码通过适配器生成已有字段。需要公开新语义时，同时评审 Schema 版本与示例。

现有 `note`、`permission` 等说明字段由兼容适配器生成固定内容，保持跨语言稳定。UI 使用诊断代码与本地化资源解释结果。英文支持沿用当前导出格式，后续协议演进另行记录。

验收覆盖：

- 权限对照包含相同栏目，集合重排保持实体对应，采集时间与翻译变化各自独立。
- 关闭实验、退后台和重新进入后，旧任务结果通过提交检查，受限缓存按规则清理。
- 以人工标记值验证基础、手动与对照嵌套数据的遮挡，确认原快照保持原值。
- 完整与遮挡导出匹配 Schema，字段路径唯一，人工示例与实际导出共用测试数据。

先补纯规则和会话测试，再替换调用入口。既有设备测试继续承担平台 API 与界面集成验证。
